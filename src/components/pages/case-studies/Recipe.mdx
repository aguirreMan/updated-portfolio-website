<CaseStudySection
  id="overview"
  title="Overview"
>

Recipe applications seem straightforward until they rely on live, third-party data. Search, ingredient scaling, nested API responses, request limits, and inconsistent data structures quickly introduce challenges beyond simply displaying recipes.

I built this full-stack application with React, TypeScript, Express, and the Spoonacular API to explore those problems. The architecture includes backend data transformation, SQLite caching, typed API contracts, and reusable frontend logic designed to make recipe discovery and serving adjustments more reliable and maintainable.

</CaseStudySection>

<CaseStudySection

The project originally began as a community college assignment using
hardcoded recipe data.

After graduation I revisited the project and rebuilt it around the
Spoonacular API so recipes could be searched dynamically instead of being
maintained manually.

Over time the project went through several rewrites as I learned more about
React, TypeScript, routing, backend development, and frontend architecture.

</CaseStudySection>

<CaseStudySection
  id="technical-decisions"
  title="Technical Decisions"
>

One major improvement was replacing fragile string parsing with strongly
typed data models.

The original implementation extracted ingredient amounts from formatted
strings.

```tsx title="Original implementation"
const parts = currentDataString
  .split(':')[1]
  .trim()
  .split(' ')

const originalAmount = parseFloat(parts[0])
```

After migrating to TypeScript, ingredient measurements became explicit
objects instead of parsed strings.

```tsx title="MeasureUnit.ts"
export interface MeasureUnit {
  amount: number
  unitShort: string
}
```

The scaling logic then became straightforward arithmetic.

```tsx title="scaleServings.ts"
const scaledAmountUS =
  ingredient.measures.us.amount * scaleFormula
```

Using typed API contracts made refactoring safer and reduced runtime bugs
caused by unexpected response shapes.

</CaseStudySection>
